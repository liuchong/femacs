Forging a Trusted Lisp-Extensible Editor Core in Rust. 以 Rust 锻造可信、可演进的 Lisp 可扩展编辑器内核。

Fe (repository and command name femacs) rebuilds the C runtime, evaluator, bytecode virtual machine, garbage collector, and display engine in Rust — paired with a native Swift Cocoa frontend on Apple Silicon macOS — while retaining existing Lisp libraries, package workflows and the portable dump pipeline.

Fe（仓库与命令名 femacs）用 Rust 重建经典 Lisp 可扩展编辑器的 C 运行时、求值器、字节码虚拟机、垃圾回收器与显示引擎，在 Apple Silicon macOS 上配合原生 Swift Cocoa 前端，保留既有 Lisp 库、扩展包工作流与便携式 dump 管线。

Why Fe? Iron, Rust, and the Living Lisp Machine 为什么叫 Fe？铁、铁锈（Rust）与活的 Lisp 机器

Preserving decades of Lisp user workflows while replacing fragile C runtime internals with explicit, auditable Rust boundaries. 以保留数十年沉淀的 Lisp 生态与交互习惯为目标，将底层 C 运行时替换为边界清晰、可审计的 Rust 实现。

The Name: Fe & Rust Fe · 26

Fe is the chemical symbol for iron (Latin ferrum); rust is iron oxide formed when iron reacts with oxygen. The name connects the editor directly to the language its core is forged in: a durable iron substrate engineered in Rust.

The repository and command-line driver remain femacs so build scripts, packages, and developer muscle memory stay immediate and recognizable.

Existing Lisp Workflows Compatibility First

An extensible editor is defined by the Lisp code that lives inside it: Org, Magit, Eglot, TRAMP, Dired, Eshell, and personal init files. Rewriting the editor from scratch with a different extension language would leave that world behind.

Fe retains owned Lisp, input-method, data and test trees with their generation inputs. It executes real .el / .elc files and creates a .pdmp portable dump. Compatibility repairs are tracked explicitly.

Modern Native Stack Rust + Swift

Where the C reference relies on preprocessor-heavy C, Objective-C, and Autotools/Makefile build glue, Fe uses a Rust core (src/), a Swift Cocoa backend (platform/macos/), Cargo workspace orchestration (xtask/), and standalone Python resource generators (tools/).

Every runtime invariant — tagged Lisp_Object layout, bytecode stack frames, and GC root registration — is explicit in Rust code.

Build & Launch the Standalone Terminal Binary

Generates build inputs, compiles the Rust core, dumps emacs.pdmp, and launches in terminal mode.

# Prerequisites: Xcode Command Line Tools, Python 3.9+, rustup, and gawk (brew install gawk)
cargo run -p xtask -- build-terminal

# Verify version and launch interactive terminal session without user init
build/terminal/port/src/emacs --version
build/terminal/port/src/emacs -Q -nw

# Evaluate a batch Lisp expression directly
build/terminal/port/src/emacs -Q --batch --eval '(princ (emacs-version))'

Build & Launch the Native Swift Cocoa App Bundle

Compiles the Rust core + Swift Cocoa bridge and assembles dist/macos/Femacs.app.

# Build the standalone macOS GUI application bundle
cargo run -p xtask -- build-macos

# Launch via macOS LaunchServices or run the executable with a clean environment
open dist/macos/Femacs.app --args -Q
dist/macos/Femacs.app/Contents/MacOS/Femacs -Q

Verify Repository Layout & Independent Resource Generation

Generates charsets, Unicode tables, globals.h, and ldefs-boot.el from committed repo inputs without a reference checkout.

# Verify root repository layout and committed bootstrap inputs
python3 tools/test-repository-bootstrap.py

# After building the terminal product, regenerate resources from owned inputs
python3 tools/bootstrap-resources.py --program build/terminal/port/src/emacs --family all

Run Local Functional Acceptance (Batch + Opt-In GUI/IME)

Runs batch smoke, terminal PTY lifecycle, core ERT suites, and optional live Cocoa window + CJK IME composition checks.

# After building both products: inspect existing products and run local workflows
python3 tools/local-acceptance.py --out build/acceptance/local-run

# Optional live GUI/IME checks require the two compiled event helpers; see the macOS guide
python3 tools/local-acceptance.py --gui --ime --sender build/macos-acceptance/macos-events --sources build/macos-acceptance/input-source --out build/acceptance/local-gui-ime

Package macOS DMG & Run Runtime Benchmarks

Produces a signed/checksummed .dmg disk image and measures workload latency/throughput.

# Package the existing app into a fresh release directory
cargo run -p fe-packaging -- macos --app dist/macos/Femacs.app --out dist/releases/local

# Run runtime workload benchmark suite against the terminal build
python3 tools/bench.py --prog build/terminal/port/src/emacs --rounds 5 --out build/bench/local
