# macOS 独立复核与功能性收尾（2026-10-22）

基线 `d2f4f774`，Darwin arm64。本对话亲自读相关代码、构建和运行；原 goal 保持暂停。
默认交付仍为 O2 + switch VM。没有把失败的 asm 候选或 PGO 自动设为默认。

## 现在可以使用的版本

- `xtask build-units` 全量重编 **680** 个 Rust 单元，`gate-load` 从端口对象链接，
  编码/换行门 **15/15**，重新 dump **13,025,648 bytes**；命令均退出 0。
- 系统 `script` 提供真实终端，运行 `build/port/src/emacs -nw -Q <文件>`；
  实际输入一行、`C-x C-s` 保存，再 `C-x C-c` 正常退出 **0**；保存内容与输入一致。
  第一版自动化 PTY 未回复终端查询而卡住，已回收该次所属进程；补终端握手后完成。
- 新鲜默认程序对固定参照运行 **92 条差分输入，0 mismatch**；比较 stdout 和退出码，
  此次未启用 stderr 逐字节比较。以上证明 macOS 终端版的构建及基本编辑闭环可用。
- 未重跑完整 ERT、Android 或 Cocoa GUI；不能把这次小范围复核写成“所有功能完全一致”。
  原 ERT 文件汇总、零用例及开发版参照的限制仍见 [调查](vm-investigation.md)。

## 自己验证过的性能和快速修正

此前本对话只验证过功能探针，没有独立复现性能；本次补做，不能沿用此前口头结论。
先写齐完整复核计划和探针，再集中构建/验证。没有重写算法或修改默认生产代码。

归档 asm 的 18 处整数检查接受低两位 **0**，而 `include/lisp.rs` 的 fixnum 低两位是 **2**。
所以原候选不能直接用来判断正确整数快路的收益。本次只做一次隔离修正：
同一程序提供 old-tag=0/fixed-tag=2；后向跳转回原 Rust safepoint；先恢复 LR 再释放栈。
候选使用单独对象、链接、dump；临时接线源文件在 finally 中按原字节恢复，未污染默认产物。

修正模式启动即 **exit 255**：合法 `C-h` 被误判为非法 key definition，尚未进入评测。
因此没有跑它的性能或宣称通过 92 条输入；这是本次修正候选的功能失败，决定放弃，未深入修复。
候选 gate 的 15 项无读数来自实际错误，不是 15 项编码算法已经分别定位到差异；
该门重设环境会丢弃 `FEMACS_BC_HOT=0`，所以“off gate”标签本身也不代表 off 实际生效。
另以显式环境单独关闭热叶后，候选能启动、dump，作为接线开销对照。

同机顺序交替，固定 `tools/pgo/eval.el`，每侧三轮取中位数（ms）：

| 项目 | 新鲜默认 | 固定参照 | 隔离候选 off | 隔离候选 old-tag |
| --- | ---: | ---: | ---: | ---: |
| bc-loop | 2.8241 | 1.7810 | 3.7680 | 16.6452 |
| bc-sum | 6.0310 | 4.4532 | 6.7890 | 18.4741 |
| bc-car | 2.8229 | 1.8890 | 3.7560 | 16.4931 |
| load | 4.5581 | 1.9341 | 4.5059 | 4.5290 |

默认三个字节码项为参照 **1.35–1.59 倍**，load 为 **2.36 倍**，性能仍未达原要求。
old-tag 模式明显更慢；off 也承担每条指令检查开关等接线成本，不能冒充默认。
本候选有共同的后跳/LR 修改，不是对旧归档逐字节重建；不与旧六项读数混称一次实验。
三轮足以暴露这里的明显退化，不是完备性能研究；不能推导“性能绝无提高空间”或全归因派发。
结论是：**本次没有快速、正确且可用的提速方案，按用户决定保留可用功能版本并停止。**
