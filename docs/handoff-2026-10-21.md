# 交接快照（2026-10-21，功能性收尾）

## 一句话状态

转写 **590/590**；DoD **7/8 = 87.5%**。唯一未达是性能（第 7 条）；真实 VM 的 asm 热叶
尝试已实测失败并回退，默认仍在原 switch VM / O2 构建上。用户已决定工作停在这里，不再为
性能 DoD 自动恢复开发。

## 本次实际尝试与结论

1. **PGO**：O2 / generate / use 三阶段构建、指纹、重签、dump、配对、smoke 全通过；7 轮
   11 项 median 全部不慢于 O2（0.757–0.969×），bytecode 由 1.83–1.85× 收窄到
   1.46–1.47×。但相对参照仍有 bytecode 1.27–1.47×、`load` 2.0439×，DoD-7 未达。
   PGO 只保留为候选，**默认构建仍是 O2**。
2. **纯代码生成替代**：`opt-level=3`+PGO 与 `target-cpu=native` 均无净收益（部分项更慢），
   已否证并丢弃。
3. **asm 热叶**：按讨论实现了 256 项表与真实热 opcode（stack、constant、eq、fixnum 快路、
   varref/varset、前后向分支），慢路回原 `exec_byte_code`，`sys_setjmp`/shared tail 未搬。
   真实 VM 六项 A/B 全部变慢（`bc-loop 10.88→23.45 ms`、`bc-car 22.38→53.57`，约
   1.4–2.4×）。原因是每次 dispatch 的状态交接与慢路返回/重入成本超过热段收益。已断开
   include/调用、恢复 switch、重编/`gate-load`/`dump`/smoke 复绿；源码保存在
   `spikes/bytecode-hot/` 仅作证据。**没有把这次失败写成“所有 asm 方案都不可能”。**
4. **非法 opcode**：`bytecode.rs` 默认臂现在对 `op < Bconstant` 报
   `Invalid byte opcode`，与参照 live threaded 的 `insn_default` 一致；`opcode 0` 仍走
   `CASE_ABORT`。`op >= Bconstant+const_length` 仍按参照非 SAFE 表行为，未额外加保护。

- `verify-dod --full`：所有实际运行的 row `ok`，1,219 s / 峰值 1.10 GB；DoD-7 未运行、
  记未达。日志：`docs/baseline/pgo-20261021/verify-dod-full.log`。

  证据：`docs/baseline/ert-final-20261021.tsv`、`ert-gc-final-20261021.tsv`。
- 生成物、原样树、平台结构门、签名提交门、`gate-fast`、`gate-load`、`dump`、smoke 均绿。

## 未验收 / 不能宣称

- **逐用例 ERT 身份/结果一致未被证明**：`check-ert.py` 只解析 summary 的 ran/expected/
  unexpected；TSV 的 `same` 是文件级计数，564 份中 63 份 `same` 两侧 ran=0。
- **新候选的新鲜完整验收未做**：`verify-dod --full` 不重跑 L5；Android 行只检查旧图片
  存在，退出 0 不等于新候选的完整平台验收。
- **最新稳定版兼容未证明**：固定参照是 32.0.50 开发版，没有最新稳定版专门对拍。
- **恶意/畸形字节码**：只修了 `op < Bconstant` 的默认臂；整体非法字节码防护未证明。
- **性能因果未隔离**：PGO `load` 2.0439×ref；没有热点采样/因果实验，不能把剩余差距全部
  归因于 bytecode 派发。
- **清理残留**：`build/pgo/use3`（约 363 MB，被否决的 O3 构建）仍在；清理命令连续遇到
  审批服务 `server_error`，未绕过审批。临时目录中的运行日志是临时副本，长期证据已放入
  `docs/baseline/pgo-20261021/`。
