G4 construction scope is defined in [tooling-modernization.md](tooling-modernization.md). This matrix records retained obligations and their verified boundaries through `6065cf1b` (2026-11-20), never unearned certificates.

| Surface | Retained obligation | Evidence boundary / present gap |
| --- | --- | --- |
| macOS arm64 terminal | Independent source generation, build/dump, classic editing keys, files, Info and abnormal TTY paths | Verified from clean `git archive` export and workspace rebuild (`6065cf1b`): `terminal-keys` (`26/26`), `terminal-files`, `terminal-user-init`, Info manuals, and `6`-case no-controlling-TTY (`test-goal-stability.py` `16/16`). Terminal binary remains checkout-local (not bundle-relocated). |
| macOS arm64 Cocoa | Rust/Swift native app, signed complete resources, relocatable package, classic input, multi-window IME and external Finder drag | Verified at `6065cf1b` ([Stage I closure](../maintenance/releases/2026-11-20-stage1-ga1-ga2-ga3-closure.md)): hidden-export relocated `--batch` + `NSWorkspace` GUI startup (`17` `@rpath` dylibs), strict ad-hoc `codesign` (`spctl --assess` `exit 3` recorded as unnotarized local-trial boundary), `gui-keys` (`26/26`), `gui-files`, `gui-background-gc` (`8/8`), `steady`/`switch`/`multi` IME (`s1-ime-multi`), and external Finder icon-view drag (`s1-finder-drag`). |
| Android arm64 | Owned Rust/Kotlin/config/source inputs, normal/checking native links, signed package and current owned emulator acceptance | Existing manifest min API21 and target37 remain. | Android API21/22 compatibility | Keep the existing minimum; use only floor-or-newer branches | Source floor proof, three extracted-method JVM fixtures across21/22/23/24/26/30/36 and actual Kotlin/dex compile are separate from real API21 device certification. That device certification is not claimed. |
| Android Java/Kotlin | Current latest LTS JDK25 at this dated stage; complete owned Kotlin closure and stdlib in dex | `--release17` is target bytecode, not permission to install an old JDK. Missing current tools fail visibly. No ambient/JBR downgrade. |
| Android other ABIs; Linux; Windows; Haiku; other retained targets | retained/deferred source and applicable raw inputs | No platform was retired because it lacks current-machine tests. A future support retirement needs its exact scope and impact. |
| Raw Lisp/data/manuals/resources | Preserve owned originals and generation inputs | Generated files are rebuilt from those inputs. Required Python/AWK generators, Swift/Kotlin platform code and compiler audit fixtures stay. |
| Performance/native/collector candidates | G5 measurements precede G6/G7 source-bound designs and real VM candidates | G4 does not introduce a VM, dispatch, JIT or collector algorithm change. Old negative experiments remain evidence. |

Android device modes create a fresh run-owned AVD, adb server and explicit serial. Inspection/dump requires an explicit receiver and is read-only. No user AVD replacement, global server reset, root, uninstall or shared diagnostic deletion is part of the new lifecycle. A structurally valid signed APK is not device acceptance; a diagnostic or old image is not readiness.

## Standalone Lisp runtime & CLI (`elisp`, `lisp`, `lisp-std`, `lisp-vm` `v0.0.1`)

The standalone general-purpose Lisp crates ([design spec](design/lisp-core.md)) are built without `cc`, CMake, or external C `-sys` libraries and carry the following verification boundaries at `v0.0.1`:

| Surface | Status | Evidence boundary |
| --- | --- | --- |
| macOS (`aarch64-apple-darwin`) | Verified (real host) | Zero-warning 14-target build/check matrix, `lisp-vm` (`12/12` + `17/17` `isolate_vm`), `lisp-std` (`8/8`), `lisp` (`23/23` + `22/22` `vm` + `20/20` zero-VM + `engine_integration` + `std_batteries_integration`), `elisp` (`4/4` + `cli_integration`), `fe-test` (`--suite self` `9/9`, `--suite all --no-cache` `39/39`), `otool -L` (`/usr/lib/libiconv.2.dylib` & `/usr/lib/libSystem.B.dylib` only), 4-crate `cargo package` isolated extraction rebuild (`elisp 0.0.1`), and isolated real-network npm + `install.sh` smoke tests. |
| macOS (`x86_64-apple-darwin`) | Cross-compile + Mach-O verified | Clean `--release` cross-compiled Mach-O x86-64 binaries (`elisp`, `femacs`, `fe`) + `otool -L` system-dylib inspection (`/usr/lib/libiconv.2.dylib` & `/usr/lib/libSystem.B.dylib` only); **no physical Intel Mac or Rosetta runtime test** performed on this host (`v0.0.1` prebuilt archive includes the portable non-aarch64 `NEAR_STACK_TOP!` fallback from `CLN320`). |
