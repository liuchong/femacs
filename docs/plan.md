# femacs plan

[femacs](../README.md) is a one-to-one replication of GNU Emacs: every C source
of the reference tree becomes a Rust source with the same file name, the same
identifiers, the same structures and the same semantics, and the Emacs Lisp
tree is copied unchanged.

- **Baseline**: the `emacs/` checkout at `fd7afced403` (GNU Emacs 32.0.50),
  git-ignored and read-only.
- **Execution manual**: [port-plan.md](port-plan.md) — the full specification:
  the twelve dimensions of "identical", the preparation stage, the per-file
  loop, the parallel workflow, the gates and the definition of done.
- **Ready-to-paste goal**: [goal.md](goal.md).
- **File-by-file map**: [port-map.md](port-map.md), generated by
  `tools/gen-port-map.py`. It is data, never hand edited.

Documentation languages: this file and [its translation](i18n/zh-CN/plan.md)
follow the repository convention (English source, `docs/i18n/<locale>/` mirror).
`port-plan.md` and `goal.md` are operational texts for the person and the agents
executing the port, so they are maintained in Chinese only.

## Principles

1. **One to one, all at once.** No incremental mixed C/Rust binary, no shims, no
   temporary compatibility layer. The tree is replicated completely, then it
   runs.
2. **`unsafe` is allowed**, because the goal is to reproduce C semantics; it is
   never used to invent behaviour the C source does not have.
3. **Names are preserved** — files, functions, macros, structs, globals, subrs,
   command-line switches, and the layouts behind them (`#[repr(C)]`, verified by
   compile-time assertions on both sides).
4. **The error model is preserved** — `sys_setjmp`/`sys_longjmp` with
   `record_unwind_protect`; no Rust `Result` plumbing, no panic across FFI.
5. **The collector is preserved** — Emacs' own allocator, conservative stack
   scanning, `staticpro`/`gcpro` equivalents, no Rust global allocator.
6. **The Lisp tree is immutable** — `lisp/`, `leim/`, `test/`, `etc/`, `doc/`
   are copied byte for byte; tests are never skipped or deleted.
7. **Generated artifacts stay generated** — `config.h`, `lisp.mk`,
   `emacs-module.h`, `etc/DOC`, the unidata and charset tables.
8. **Verification is the upstream test suite** — ERT against the port
   (`make -C test EMACS=… check`), differential runs against the reference, subr
   table comparison, and bidirectional `.elc`/dump/module interchange.

## Method

The approach follows the practice established by comparable rewrites: a porting
guide and a lifetime table written before any code (`PORTING.md`,
`LIFETIMES.tsv`), a three-file trial to calibrate them, then one mechanical pass
over every file, with `cargo check` errors used as the work queue, one
implementer plus two adversarial reviewers per file, and the original test suite
as the acceptance criterion. [port-plan.md](port-plan.md) turns that into
batches, gates and a per-file checklist; [goal.md](goal.md) is the pasteable
form of it.
