Four-crate workspace layering

Standalone Lisp crates stay strictly isolated from editor binaries: lisp-vm owns the bytecode VM and opt-in isolate_vm per-thread storage; lisp-std provides 100% pure-Rust (#![forbid(unsafe_code)]) HTTP/TLS/SQL/codec modules; lisp unifies Engine, No-GIL pools, warm .pdmp caches, and package management; and elisp packages the CLI and TTY REPL. Editor targets disable standalone batteries.

Evaluator and bytecode VM

The standard build uses the Rust evaluator and bytecode VM. Native compilation is available in an optional build using libgccjit. The review records where native execution helps and the compile-time and runtime costs that kept it optional.

Read the runtime design ↗

Garbage collection

The standard collector remains the default. An optional build exercises real automatic young-generation collections. The project records correctness and workload measurements separately and kept the young collector optional after its measured regressions.

Read the runtime and GC acceptance record ↗

Native Cocoa and terminal display

The Swift Cocoa frontend handles Mac frames, input and desktop integration. The separate terminal product keeps the text interface. See the support matrix for the status of other platforms.
