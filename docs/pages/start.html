Build, Try & Verify Fe on macOS 在 macOS 上构建、试用与验收 Fe

Fe builds directly from this repository on aarch64-apple-darwin without requiring an external reference checkout or prebuilt C object tree. Follow the steps below to build the terminal binary, assemble the native Swift Cocoa app bundle, and run local acceptance.

Fe 可在 aarch64-apple-darwin 上直接从本仓库独立完成源码构建，无需外部参照源码检出或预编译 C 目标树。按以下步骤即可构建终端二进制、生成原生 Swift Cocoa 应用包并运行本地验收。

1. Host Prerequisites & Support Matrix 1. 主机环境依赖与平台支持矩阵

Documented in docs/repository-bootstrap.md and docs/support-matrix.md. 详见 docs/repository-bootstrap.md 与 docs/support-matrix.md。

Required Host Tooling macOS arm64

Ensure the following four tools are installed before running xtask or bootstrap-resources.py:

  • Xcode Command Line Tools (xcode-select --install) — provides clang, swiftc, ar, codesign, and hdiutil.
  • Rust toolchain via rustup — the dated toolchain pinned in rust-toolchain.toml targeting aarch64-apple-darwin.
  • Python 3.9+ — drives tools/bootstrap-resources.py, tools/local-acceptance.py, and tools/bench.py.
  • GNU Awk (gawk) — required by admin/charsets/*.awk recipes during charset generation (brew install gawk).

Platform Tier Summary Support Matrix

The docs/support-matrix.md separates retained support obligations from actual acceptance evidence:

  • Locally verified scope: Apple Silicon macOS (aarch64-apple-darwin) — terminal binary + Swift Cocoa Femacs.app + portable dump.
  • Retained / separately validated: Linux, BSD, Windows and Haiku backends and the Android Kotlin layer remain in tree; this site does not claim current device acceptance for them.
  • Scoped infrastructure cleanup: Removed tools and their replacements are individually recorded in docs/retired-scaffolding.md.

Run commands from a tracked checkout. Build both products before local acceptance. Compiler and editor workloads belong under your resource controller. Receipt, benchmark and release output directories must be fresh; GUI/IME checks need an unlocked desktop and the event helpers described in the macOS guide. The local app is ad-hoc signed and not notarized.

2. Standalone Build, Package & Acceptance Commands 2. 独立构建、打包与本地验收命令

Switch tabs to inspect each stage of the standalone build and verification pipeline. 点击切换各构建与验收阶段命令，支持一键复制。

Stage A — Verify the Repository Layout

Checks the root layout and committed generation inputs; the build steps below generate resources automatically.

python3 tools/test-repository-bootstrap.py

Stage B — Build & Run the Terminal Binary

Produces build/terminal/port/src/temacs, build/terminal/port/src/emacs, and emacs.pdmp.

cargo run -p xtask -- build-terminal

# Run interactive terminal UI (-nw) without loading personal init files (-Q)
build/terminal/port/src/emacs -Q -nw

# Run batch expression evaluation
build/terminal/port/src/emacs -Q --batch --eval '(princ (format "Fe %s on %s\n" emacs-version system-configuration))'

Stage C — Build & Try the Native Swift Cocoa Application

Produces dist/macos/Femacs.app with bundled Lisp, charsets, icons, and portable dump.

cargo run -p xtask -- build-macos

# Launch the GUI app bundle with a clean profile
dist/macos/Femacs.app/Contents/MacOS/Femacs -Q

# Or open through macOS LaunchServices
open dist/macos/Femacs.app

Stage D — Package Distributable macOS Disk Image (DMG)

Documented in packaging/README.md; creates .app, .dmg, and SHA256SUMS.

cargo run -p fe-packaging -- macos --app dist/macos/Femacs.app --out dist/releases/local

# Inspect generated release artifacts and SHA-256 digests
ls -lh dist/releases/local/
cat dist/releases/local/SHA256SUMS

Stage E — Run Local Acceptance & Differential/Benchmark Tools

Verifies batch evaluation, terminal PTY rendering, ERT suites, and optional live GUI + IME checks.

# Default local acceptance run (terminal + macOS bundle + batch/PTY/ERT)
python3 tools/local-acceptance.py --out build/acceptance/local-run

# Optional live GUI/IME checks require the two compiled event helpers; see the macOS guide
python3 tools/local-acceptance.py --gui --ime --sender build/macos-acceptance/macos-events --sources build/macos-acceptance/input-source --out build/acceptance/local-gui-ime

# Run performance workload benchmark suite
python3 tools/bench.py --prog build/terminal/port/src/emacs --rounds 5 --out build/bench/local

Essential Chords (C- = Control, M- = Option/Esc) Keybindings

Chord Command Action
C-x C-f find-file Open or create a file in a buffer
C-x C-s save-buffer Save the current buffer to disk
C-x b switch-to-buffer Switch between open buffers
M-x execute-extended-command Run any interactive Lisp command by name
C-g keyboard-quit Cancel current minibuffer prompt or operation
C-h f / C-h v describe-function / variable Inspect live docstrings and source definitions
C-x C-c save-buffers-kill-terminal Prompt to save modified buffers and exit Fe

macOS Cocoa GUI, Modifiers & CJK IME Swift Cocoa

The macOS app bundle (dist/macos/Femacs.app) bridges Cocoa windowing and text input in Swift (platform/macos/):

  • Modifier Keys: Customize ns-command-modifier, ns-alternate-modifier, and ns-control-modifier in Lisp just as on the reference macOS port.
  • CJK Input Methods (IME): Implements the NSTextInputClient composition and commit protocol. Local Chinese multi-window workflows have scoped acceptance; this is not certification of all Japanese, Korean or other input sources.
  • Safe Tryout Profile: Launch with -Q or --init-directory=./trial-profile to test packages without altering your primary ~/.emacs.d.
