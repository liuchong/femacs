# G7: the young-cons implementation bound to roots, stores and lifecycles

This binds the bounded root/store/barrier inventory in
[runtime-modernization.md](runtime-modernization.md) to the collector that
actually runs (`src/runtime_gc_collector.rs`, feature
`femacs_gc_generational`). It is a source-bound argument, not a file list: every
row names the code that performs the operation, the mechanism that keeps a
minor safe, and the evidence that exercised it. Line numbers are the current
tree (`a9abf396` onward); a later edit must re-derive them.

## Cycle pipeline (what a minor actually does)

`garbage_collect_impl` (`src/alloc.rs`): `choose_cycle` 6743 → `prepare_cycle`
6747 → `trace_remembered_owners` 6760 → static roots 6764 → lread/terminals/
keyboards/threads 6770-6773 → port stack substitute 6776-6800 → stack scan →
weak fixpoint 6895 → finalizers 6882-6889 → `start_sweep` 6900 → `gc_sweep`
6901 → `commit_cycle` 6907.

A minor is **not** a cons-only sweep: `gc_sweep` (8369) sweeps strings, conses,
floats, intervals, symbols, buffers and vectors every cycle. What makes it
"young" is that old cons cells are kept through `oldbits` and every retained old
cell has its children re-submitted:

| Phase | Kernel | Consequence |
| --- | --- | --- |
| `choose_cycle` 285 | reason 0 only when mode is young, no foreign/unknown producer, registry valid, no doomed finalizer, `totals[5] < 3` and both retention lead checks pass | any doubt selects Full with a reason code, never a silent minor |
| `prepare_cycle` 309 | freezes the registry prefix, merges `oldbits` into `gcmarkbits`, and re-traces the children of every unmarked old cell ("revived") 352-379 | a live old cell never loses a child because a previous sweep cleared its mark |
| `trace_remembered_owners` 382 | marks the frozen registry prefix 397-401 and, for every old cell, its dirty children (or the whole block when `raw_tainted`) 405-421 | owners recorded in earlier cycles and cells written through an escape are traced conservatively |
| `commit_cycle` 431 | rebuilds `registry.valid` from cycle validity, overflow, counter exhaustion, foreign and unknown flags; advances the cadence bases on a minor | an incomplete cycle disables further minors until a Full re-establishes the registry |
| `abort_cycle` 458 | non-local exit invalidates the registry and the cycle | an interrupted mark cannot leave a half-valid remembered set |

## Stores: every write entry and its mechanism

| Write entry | Code | Mechanism for a minor |
| --- | --- | --- |
| `XSETCAR` / `XSETCDR` | `include/lisp.rs` 925/934 | call `femacs_gc_cons_written` after the store; `written` 508 sets the dirty bit only for an already-old cell |
| `XCONS`, therefore `xcar_addr`/`xcdr_addr` | `include/lisp.rs` 895, 903, 908 | call `femacs_gc_cons_escaped`; `escaped` 516 sets `raw_tainted` for the whole block, so a pointer write through an address is treated as a write to every old cell of that block |
| Native code generated by `comp.rs` | emit at 3861/3883, import at 6184, dispatch slot 1084 | native code calls `femacs_gc_cons_written` through the same C symbol |
| Any dynamically loaded module | `dynlib.rs` 60 before `dlopen` | `unknown_producer_loaded` latches `UNKNOWN_PRODUCER`, which makes every later cycle Full with reason 8, permanently |
| Non-cons stores (`ASET` 1406, `SET_SYMBOL_VAL` 1560, hash key/value vector `fns.rs` 5478-5493, buffer/frame fields) | direct writes, no barrier | not needed for correctness: the owner is marked and traversed whenever it is reachable, and an unreachable owner is garbage. A non-cons object is never retained on the strength of an untraced store |
| Stack cons cells (`AUTO_CONS`, `STACK_CONS`, `AUTO_FRAME_ARG`) | `include/lisp.rs` 3777-3860, `include/frame.rs` 1873-1887 | not heap cells: `heap_cell` 471 rejects them, so no barrier applies. Their car/cdr words are inside the scanned stack range, and the conservative scan marks those children directly |
| Free-list writes | `alloc.rs` 3090, 3135-3136, 8095 | performed after `clear_cell` 3086/3134 cleared the age bits, so the cell is young and unaged; a stale old identity cannot survive reuse |
| Dumped objects | `heap_cell` 476 rejects `pdumper_object_p`; `pdumper_clear_marks` in `gc_sweep` 8398 | a pdump object is never remembered; it is marked through the pdumper bit each cycle |

## Lifecycles

| Transition | Code | Rule |
| --- | --- | --- |
| Process/owner start | `activate_owner` 179, `reset_process` `alloc.rs` 8709 | a new owner resets registry, flags and cadence state |
| Allocation | `note_allocation` `alloc.rs` 643/3141, `act` 183-191 | only counters and an arm flag; never a collection from an allocation primitive |
| Free/pointer release | `before_pointer_change` `alloc.rs` 828/847/1215/1478, `before_storage_change` 5098 | a remembered owner inside a freed or reused range invalidates the registry (reason 6) before the allocator can reuse it |
| Cell free | `clear_cell` `alloc.rs` 3086/3134 | clears `oldbits`/`dirtybits` for that cell |
| Sweep keep | `survivor` 548, `survivor_word` 554 (`alloc.rs` 8057/8101) | promotion sets `oldbits`; the first promotion is counted |
| Sweep dead | `swept_dead` 561 | clears both age bits and counts a dead young cell that was not old |
| Mark bookkeeping | `note_cons_marked` 527 (`alloc.rs` 4660/7855), `note_marked_noncons` 272 (7 sites) | location proof for the current token; non-cons owners enter the registry only while `capture_registry` is on |
| Registry bounds | `REGISTRY_CAPACITY` 262144, `INDEX_CAPACITY` 524288, `MAX_PROBES` 1024; overflow 66-71 | overflow clears validity so the next cycle is Full |
| Non-owner thread | `owner` 137-139 sets `FOREIGN` | every later cycle is Full with reason 7 |
| Exit/abort | `abort_cycle` 458 | invalidates cycle and registry; no partially armed guard survives |

## Full fallbacks (reasons)

`choose_cycle` 285-308: 1 startup, 2 explicit `garbage-collect`, 3 major-layout
control, 4 three consecutive minors, 5 retention cap, 6 registry-invalidated
(range freed/overflow carries its stored invalid reason), 7 foreign thread,
8 unknown producer (`dlopen`), 9 `memory-full`/`purify`, 10 unwind abort,
11 counters/token exhaustion, 12 doomed finalizers. 6-12 are all Full, never a
minor.

## What is still not established

1. **A complete (not bounded) store census.** The bounded inventory covers 532
   files and 67,043 indirect/aggregate assignments; this binding covers every
   *cons* write entry, but a census that proves no direct cons store exists
   outside the listed sites would still need a typed analysis.
2. **Corpus-wide young stress.** `check-ert.py` fixes the child environment to
   `HOME`/`PATH`/`LC_ALL` and passes no `FEMACS_*`, so a 564-file sweep with
   `FEMACS_GC_COLLECTOR=young` is not expressible through that entry. The
   native-young profile run above is the largest young workload on record, not a
   corpus sweep.
3. **Discriminating barrier tests are not expressible from Lisp.** A dirty or
   tainted trace can only be observed when an old cell is retained while *not*
   being marked, and Lisp cannot hold a cons pointer without a root. The revived
   traversal already re-submits every unmarked retained old cell, so a Lisp test
   cannot separate the two mechanisms. A discriminating test needs direct cons
   pointers (a Rust/`--batch` test hook) and is not part of this batch.
4. **Native and FFI writers are covered by refusal, not by tracing.** `dlopen`
   and non-owner-thread cycles force Full; that is a deliberate safe fallback,
   not evidence that foreign writes are instrumented.
