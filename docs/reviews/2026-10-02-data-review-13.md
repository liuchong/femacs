## What the round's own checks caught and what fixed them

1. `_ => eassume! (false)` as a `match` arm body — `eassume!`'s `#[cfg]` lands in
   expression position (E0658).  All five catch-all arms are now blocks.
2. `#[allow(unreachable_patterns)]` on a `match` expression has the same problem, so the
   lint moved to a file-level `#![allow(unreachable_patterns)]` with a comment naming
   C's `default: eassume (false)`.
3. Rust has no postfix `++` and no `~`; `argnum++`/`pos++` are `+= 1`, `~XFIXNUM` is
   `! XFIXNUM`.
4. `X < NAME as T` parses as generic arguments; the comparison is parenthesised.
5. `DEFUN!`'s parameter pattern is `$arg:ident : $ty`, so `mut` cannot appear in an
   argument list; `Frem`, `Fmod` and `bool-vector-not` re-bind their writable parameters at
   the body's top level (the recorded `let mut X = X;` convention).
6. The generator that turned `syms_of_data`'s 120 `defsubr` and 138 `DEFSYM` lines into
   Rust silently dropped `DEFSYM (Qsubr_native_elisp, "subr-native-elisp");` (C's trailing
   `/* Deprecated name.  */` breaks a line-anchored match).  It is restored by hand.
7. `lisp.rs`'s `string_to_number` declaration has a `ptrdiff_t *` parameter, which the
   probe's type table cannot spell, so it carries the reference prototype in a `/// C:`
   line (P-55).  Without it the probe emitted `*mut ptrdiff_t` into C and `gate-probes`
   failed — the declaration is round 12's and had never been probed.
8. The `va_arg/next_arg` token family has no exemption mechanism, so C's `next_arg:` label
   and its `goto` had to reappear as real Rust spellings: the two drivers name their loop
   `'next_arg` and spell the back edge `continue 'next_arg`, and the "skip the switch once"
   jump is the `skip_switch` flag.
9. `TYPE_MAXIMUM (mp_bitcnt_t)` has no mirror (P-26), so `Fash` writes `mp_bitcnt_t::MAX`;
   the `macro-body-notes` row records it, as for `esprintf`.
