Scope: `arithcompare` (the file's first `MANY` consumer and its first non-static export since

Method: reviewer A attacked the code (the nine float/fixnum/bignum combinations and every

## Reviewer A: three findings, all fixed

| # | Finding | Disposition |
| --- | --- | --- |
| A-F1 (Low) | the driver's comment said Rust's `!=` binds tighter than `&`; it is the *other* way round (Rust's `&` binds tighter, unlike C's), which `Fneq`'s unparenthesised `& Cmp_EQ != 0` right beside it proves | comment rewritten (the parentheses stay as defensive) |
| A-F2 (Low/Med) | my comment claimed C's enumerators have the enum's own type; ISO C 6.7.2.2p3 says an enumerator has type `int` (C++ is the other rule), and the mirror's *pre-existing* comment beside those constants said exactly that - so my `Cmp_EQ`/`Cmp_LT`/`Cmp_GT` retype was a deviation sold as fidelity | reverted: the three constants stay `c_int`, and the five parameter-passing sites plus `Fneq` spell the conversion C makes implicitly as `as cmp_bits_t`; the ledger records the deviation-free choice |
| A-F3 (Low) | `arithcompare_driver` was a *safe* `fn` that dereferences a caller-supplied raw pointer, so safe code could call it with a null pointer (in-tree unreachable, but unsound as an API - and the notes row compared it to `sort.rs`'s `binarysort`/`count_run`, which are `unsafe fn`) | made `unsafe fn`; the six callers are `unsafe extern "C" fn` bodies already, and the ledger says why |

A's observation worth keeping: these six subrs are the port's first `usage:` docstrings, and
`make-docfile` normalises a `usage:` keyword when it writes `etc/DOC` (two newlines, the
function name replaced by `fn`), a transformation neither the mirror nor the digest models -
recorded in the ledger for phase G.

A found no defect in: all nine combinations' directions (including the bignum-first
`mpz_cmp_d (*xbignum_val (num2), f1)` case where `lt`/`gt` invert), the tie-break blocks
(`i1 = f2; i2 = XFIXNUM (num2)` and its mirror image), the NaN paths, `eassume (sgn != 0)`,
the four `not_number_or_marker` call sites (three with `num2`, the outer one with `num1`), the
`as c_double`/`as EMACS_INT` conversions (unobservable: the tie values are bounded by
`MOST_POSITIVE_FIXNUM`), the bit packing and its precedence, the driver's loop and operand
order, the `MANY` parameter list (the gate's `param_types`), the masks and `Fneq`'s polarity,
and the docstring bodies including the trailing-space rule.
