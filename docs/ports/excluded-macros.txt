# C macros that have no Rust counterpart yet, with the reason and the construct
# that replaces them.  One `<name>\t<kind>\t<reason>` per line; the inventory gate
# reports these separately instead of counting them as missing.  Mostly src/lisp.h;
# a mirror of another header appends its own rows here.
#
# kind=syntax   : the macro spells C syntax or an attribute; the port expresses
#                 it structurally.
# kind=config   : the macro selects a configuration branch that the port fixes.
# kind=debugger : the macro exists only so a debugger can see a value.
# kind=deferred : the macro is a control-flow construct whose Rust form is an
#                 open design decision (see PORTING.md P-22); it must be
#                 resolved before the files that use it are ported.

lisp_h_Qnil	config	P-17: the port spells the Q* macros as functions (`lisp_h_Qnil ()`), which is what every call site needs; the frozen branch's `# define lisp_h_Qnil 0` (lisp.h 374) is that function's body (lisp.h 384-386's `{0}` is the struct-Lisp_Object branch this target does not take)
KVAR	syntax	keyboard.h 38: `((kboard)->field ## _)` pastes the field name — Rust has no token pasting; the port writes the field (every one it names ends in `_`) directly at each use site
Vstandard_category_table	syntax	category.h 103: `BVAR (&buffer_defaults, category_table)` - the field name is pasted, so the port writes the BVAR expansion at each use site (the KVAR row's class)
data_start	dead-text	vm-limit.c 45-47's `#define data_start ((char *) DATA_START)` sits inside `#ifdef DATA_START`, and DATA_START is absent from the frozen macro table, so the evaluator cannot decide the branch and demands both; the frozen configuration takes the `#else` branch, which *defines* the one-byte object the port mirrors
