## Actual bytecode, not the test name

The GC regression
`eval-tests-byte-code-being-evaluated-is-protected-from-gc` calls a helper
which removes its own symbol-function reference and then collects garbage.
Loading only the source file defines that helper as an interpreted closure,
so a source-only pass cannot prove this bytecode-root scenario.

Each product therefore byte-compiles its own three original files into its
isolated test tree, using its selected dump and own Lisp libraries. All three
compiler processes complete with exit 0. Each compiled artifact is separately
fingerprinted, loaded explicitly through the existing ERT bridge and verified
unchanged afterwards. The same logical file and original case IDs are retained.

A small external after-load observer writes metadata before the cases execute;
it does not redefine original functions, alter guards or wrap test bodies.
It confirms the exact loaded file and observes both `eval-tests-33014-func`
and `data-tests-popcnt` as interpreted in source mode and bytecode functions
in compiled mode on all three products. The GC case then passes in the actual
bytecode mode, including its original collect-after-redefinition assertion.
This is baseline collector/VM evidence, not proof of the experimental
generational collector or every GC root/lifetime path.

The exact executed observer payload is retained as
`tools/fixtures/stable-evaluator-mode-observer.el`, SHA-256
`7dc12977abc1e8010161c9ebeb232c29d52dbcef1dff372b26c1b6bd0b7cb9b5`.
Publishing the byte-identical fixture changes no runtime input or test outcome.

## Replay through the existing tools

Materialize a fresh, separate owned tree per product with
`python3 tools/stable-suite.py --manifest compatibility/stable-31.1/sources.json --out <owned-view> --materialize`.
This uses the verified pinned acquisition/cache and requires no optional
reference checkout. Select the built product's own executable, dump and Lisp
directory. Run its `batch-byte-compile` on the three owned source copies before
the compiled-mode executions; do not share generated bytecode across products.

Use the existing `stable-suite-batch.py` file runner and
`tools/fixtures/stable-suite-runner.el`. Keep `STABLE_SUITE_FILE_ID` as the
original logical source path; choose the owned `.el` or `.elc` through
`STABLE_SUITE_FILE`. Load the published observer before the bridge and set
`FEMACS_ORIGINAL_TEST_FILE` to that exact selected file and
`FEMACS_ORIGINAL_MODE_RECORD` to its owned metadata output. The bridge's normal
progress/result paths, isolated case environment and bound product/source
context are still required. Compiler and editor processes retain the normal
resource controller and finite deadlines. Verify actual loaded-file/helper
metadata as well as every original result and input/product identity; a
compiled suffix or successful compilation alone is insufficient.

## Identity, cost and limits

The group takes 18.061 seconds; its resource owner takes 20.044 seconds, peaks
at 143,867,904 accounted bytes and exits 0 with complete process cleanup.
Original source files, manifest/cache, harness/observer inputs, programs,
selected dumps and complete selected product libraries remain unchanged.
Raw compilation outcomes, compiled identities, loaded-mode records and all
per-case events/timings remain in `build/acceptance/g3-evaluator-modes-1`.

The original data file includes a CPU-time ratio check with 1,000 temporary
buffers, and the evaluator file includes a bounded real delayed-message wait.
Their original assertions pass; this single compatibility run is not a
controlled performance comparison or evidence of a measured speedup.

The evaluator's original error-reporting subprocesses invoke the same product
path without an explicit dump argument. They do not prove that a child loaded
the parent's explicitly selected dump. Expected ordinary nonzero Lisp-error
exits are distinct from a process signal or crash; no deliberate abort test
was selected in this group.

No P427 repair is claimed. A focused read of the existing thread lock/select
and FD-mask paths did not establish its invalid descriptor's origin; the
earlier intermittent abort and diagnostic non-reproductions remain open.
Existing remote Base64, common DNS, compiler metadata and EIEIO warning cases
also retain their own scope. Full G3/G5/G6/G7 and performance improvement
remain required; G1/G2/G4 are still three of seven delivered outcomes.

Independent review accepted this limited mode evidence. It checks products
against the reference within each mode; it is not a separate proof of every
source-versus-bytecode semantic equivalence.
Consumed test trees, bytecode copies and compilation environments are retired
in [CLN140](../cleanup/reports/2026-10-30-140-consumed-evaluator-mode-test-copies.md);
original mode/results/compilation records and artifact fingerprints remain.
