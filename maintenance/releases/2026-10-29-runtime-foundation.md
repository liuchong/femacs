# Experimental macOS runtime foundation

This source group brings the product builder, dependency capture and runtime
candidates into one coherent repository tree. Native compilation and the young
cons collector remain explicitly opt-in. The ordinary macOS configuration and
baseline products keep native compilation, generation collection, observer and
test hooks off. This source delivery does not promote either research candidate
or claim the seven-part modernization Goal complete.

## Included closure

- Owned source/config/backend identities, normal/checking product legs, copies-only
  staging, library/license capture and relative packaged runtime paths.
- Complete macOS TLS, XML, SQLite, threading, file-notification, LCMS and
  Tree-sitter connections, shared declarations and their real consumers.
- The version-bound public module API inputs and generator. No ignored reference
  tree is a product source dependency.
- Explicit native/compiler lifecycle and generational-GC/observer candidates,
  with their headers, consumers, source-bound tests and diagnostic drivers.
- The conditional Swift native subr layout and run-loop wakeup export required
  by those configurations. Unrelated Android-only JNI changes and incident
  drafts were excluded.
- Source-declaration consolidations CLN72, CLN113 and CLN132 with original block
  identities and restoration boundaries. These are not physical file deletion.

## Measured acceptance

Four baseline products built from that exact tree: normal/checking Cocoa and
terminal. Both Cocoa apps passed explicit strict signature verification. Build
and cleanup finished in 1218.312 seconds, with 883113984 accounted peak bytes.

The new four products each passed all 40 unchanged stable Tree-sitter cases:
160 new passes. The installed reference's 40 passes were reused only after
matching its complete selected identities, original inputs, harness and eight
real grammar libraries: **200 unique case-products**, zero failures, skips,
timeouts or unexecuted cases in that cohort.

Twelve new ordinary parser/node/query/GC lifecycle case-products plus three
unchanged reference cases give 15 unique passes. Four fresh two-process query
image restores plus one unchanged reference result give five scenarios. These
exercise ordinary GC ownership, not the experimental generational collector.
All selected source, program/dump/resource, harness and input identities remained
unchanged. Integration and cleanup took 32.834 seconds and peaked at 311033856
accounted bytes.

After integration, all 62 relevant existing runtime/config/ownership/manual-copy,
ABI-selection, LCMS and Tree-sitter protection cases passed. Each case ran in an
isolated process with an executable 30-second deadline; reported per-case elapsed
time includes startup. The run took 3.120 seconds, peaked at 44941312 accounted
bytes and reclaimed its processes. Compilation was reused from an initial
preparation attempt which successfully discovered 114 total existing tests but
stopped before any case because its catalog guard expected at most 100. That
raw failure remains; all 62 relevant cases were then selected, with unchanged
Android/bundle/probe modules outside this scoped guard run. No original assertion
or source was weakened.

The independent reviewer made eight actual read-only source/evidence checks and
accepted the complete group for an explicitly experimental source commit, finding
no concrete missing prerequisite or default-behavior defect in that bounded
review. This is source-coherence acceptance, not proof of all optional modes.
