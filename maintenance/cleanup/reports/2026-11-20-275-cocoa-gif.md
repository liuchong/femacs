# CLN275 — Cocoa GIF decoding

The Cocoa build had no GIF reader. An explicit GIF icon caused the optional project-tree package to abort during language-client initialization. Cocoa now uses the existing native decoder for GIF when giflib is absent. The native image error path logs the same Lisp arguments through a fixed-arity ABI so that malformed input yields an error message and a placeholder.

The prior bundle reproduced `Invalid image type 'gif'`. The first native GIF build decoded valid images but crashed in `add_to_log` on truncated GIF data. The fixed bundle passed all 14 cases in `image-loader-probe.py`, covering GIF files, GIF byte strings, malformed GIF and recovery, plus PNG, JPEG and WebP. The installed bundle also returned `(100 . 75)` for the GIF fixture on a real Cocoa frame.

Temporary projects exercised Rust and C language-server initialization and document symbols, plus font-lock for Rust, C, Python, JavaScript, TypeScript, Go, and Shell. Scoped Rust asynchronous symbol requests completed. Rust definition lookup returned the correct source location after two `content modified` retries during early indexing. No persistent editor process stall was observed in these probes.
