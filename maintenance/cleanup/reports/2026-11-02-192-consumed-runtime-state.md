## Selection and preservation

- Historical corpus/context copies: only manifest-matching regular files,
  exact context links and newly empty directories were selected. The first
  group preserves 472 generated bytecode files. The later group preserves
  476 generated bytecode files plus four original fixtures whose mode changed
  to 0770. All logs, results, environment records and materialization witnesses
  remain. Symlinks were unlinked without following targets.
- Native masters: two ended file-integration input copies matched all 1,536
  original manifest files each. Canonical retirement removed their test trees;
  only then were the verified empty master roots removed. Success/failure
  receipts and frozen input sources remain.
- Superseded builds: selection was confined to runtime, manuals and generation
  subtrees of two ended build exports. It retains 3,664 evidence files and
  202 ancestor directories within those envelopes, along with staged sources,
  top-level receipts/sidecars, process records and acceptance results. Selected
  file hard links were wholly internal; no external hard links were selected.
- Successful scratch state: only sealed, semantically complete and successful
  calls whose original retirement reported occupancy uncertainty qualified.
  All 1,101 containers completed canonical retirement, including their two
  empty parent directories. No failed, skipped or incomplete invocation was
  selected. New proxy evidence and retirement ledgers are separate; original
  results, events and `retained` owner receipts were not promoted or rewritten.
  Historical case-root inode evidence was unavailable; original persisted
  container identity and a fresh case-root admission were used explicitly.

Plans and original receipts remain private and unchanged. Earlier safe plan
failures and their evidence remain; they performed no deletion. This report
does not convert any compatibility failure, timeout, skip or incomplete cohort
into a pass. Existing products, original inputs, the trial App and unrelated
working-tree changes remain. The unsigned-bignum assertion source correction
is a separate unvalidated change; no build or runtime regression is claimed.

## Recovery and identity

Corpus/context copies can be reconstructed from retained source manifests,
frozen corpus/context bytes and materialization/link sidecars, preserving bytes,
modes and link text. Native master files likewise come from the retained corpus.
Build outputs require their retained staged sources, configuration and original
recipes to be run again; old binary identities are not promised. Scratch state
can be regenerated from the original entrypoint, product and environment recipe;
random names and native cache bytes are not promised identical. No recovery
claim includes historical inode, timestamps or extended attributes.

Every public field was compared with its retained private source identity.
Regular files carry content hashes; links carry target hashes without raw target
paths. Private raw identities provide the exact restore mapping. Public path
hashes are scoped by manifest and, for scratch state, numeric `case_id`.
