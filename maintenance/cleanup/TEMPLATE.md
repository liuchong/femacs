# CLN-YYYYMMDD-NN · 主题

- 类型：tracked 退役 / 未提交实验撤回 / 生成物清理 / 零删除检查
- 实际操作日期/时间：已知值；缺失写“未记录”
- 报告建立日期：日期；回填时明确标记
- 基线 `source_ref`：完整 Git ref；未提交内容补快照哈希
- 动作 `change_ref`：实际删除/撤回提交；忽略产物无删除提交时明确说明
- 报告提交：用本文件路径历史定位；已有补记提交写完整 ref

## 原因、替代者和影响

为何需要处理；判断依据和替代入口；哪些功能/路径可能受影响；哪些明确保留。不要把未测平台称为已退役。

## 逐项范围与证据

链接本批清单：路径、动作、删前逻辑/分配字节、内容 SHA-256 或 Git blob。源代码关联最后可恢复 ref。生成物关联源码/配置/工具链身份。原始日志需保密时，提交不含私有信息的可审计摘要/清单及原始记录哈希，明确证据缺口。

## 执行与验证

实际操作、时间和所属进程/句柄检查结果；删除结果、数量和各类字节；未删除/保留项；实际验证输入、产物身份、通过/失败和未运行范围。系统空闲空间变化没有测量就写“未测”。引用同批测试/审核证据，不把旧验收冒充新验收。

## 恢复与根因定位

明确 Git ref/旧路径或惰性补丁和 SHA-256；给出隔离恢复/重新生成命令、依赖和可能成本。没有内容哈希或环境快照时，不承诺缓存字节完全相同。写明哪些问题在清理前就存在、哪些仍待验证。

## 关联及更正

链接台账、决策、替代实现、验收摘要、相关报告。后续更正追加日期、原因和新证据；保留旧结论。
