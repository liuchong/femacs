# 清理与退役工程档案

这里管理每批删除、退役、实验撤回与生成物清理的工程记录，供排障、回溯和恢复使用。它不是用户使用手册，也不是 Agent 规则。记录入口是 [清理台账](LOG.md)，新批次使用 [报告模板](TEMPLATE.md)。原有 [丢弃日志](../../docs/retired-scaffolding.md) 保留历史分类与政策说明，并引用这里的具体报告；项目 [进度日志](../../docs/status.md) 只写摘要和记录编号。

## 组织与编号

```text
maintenance/cleanup/
  README.md       定位、记录方法与溯源入口
  LOG.md          每批一行，关联动作、报告和已知提交
  TEMPLATE.md     每批报告字段与验收清单
  reports/        日期-序号-主题.md，一份报告对应一个明确批次
  manifests/      仓库相对路径、文件身份和数量/字节清单
  patches/        仅存 Git 从未保存过的退役实验的惰性补丁
```

编号为 `CLN-YYYYMMDD-NN`，同日序号不复用。编号用于区分批次，不能替代原始操作时间。报告日期、实际操作日期、Git 提交时间分别记录；不掌握的精确时间写“未记录”。本次六项为已有记录的回填，没有执行新的删除，不宣称所有更早历史清理已逐项审计。

## 每批都提交报告

涉及删除/退役/撤回代码或清理生成物，每批都建立报告、台账行和必要清单，并提交到仓库；可与同批代码变更一起提交，纯产物清理也需要单独提交报告。未来操作在执行前记录范围、基线、路径和内容身份，执行后补实际结果、验证和恢复方法。零删除检查明确标为“未删除”，不混入删除或空间释放统计。

报告包含目的/判断依据、替代者、受影响与保留范围、操作与已知提交、删前逐项路径/大小/哈希或 Git blob、删后验证、未解决风险和恢复配方。目录级记录须展开文件清单或明确仅有汇总的缺口。补写的旧记录不能伪造哈希、时间或完整性。逻辑字节、分配字节和系统空闲空间变化分开描述。

Git 提交本身保存 tracked 文件的旧内容；报告关联最后可恢复的完整 ref、删除提交和旧路径，不另复制源码。未提交过的实验不能声称可从 Git 找回：如仍有经哈希核对的副本，将其存为惰性补丁并验证重建。普通编译缓存记录源码/配置/工具链及重建配方；没有删前内容哈希时，不能声称逐字节复原。

报告和清单使用仓库相对路径，不放密钥、账号、会话标识、机器绝对路径或完整对话。原始私有日志不直接提交；报告须提交足够的稳定证据摘要与清单，不能只有指向忽略目录的链接。补丁不是活动实现，不接入构建，也不自动恢复或执行。

## 构建与验收的实际清理出口

按P-376执行，不等整项目收尾才处理。每轮结束先核对本轮所属进程及后续消费者，保留原始失败/结果、输入与产品身份，再清无消费者的缓存和副本；读取一次各自有输出根的占用，登记本批删除与仍保留的大项及用途。归属或消费者不明时保留该项并写明，不能借此把整棵历史构建树永久保留。

- 搬移验收：每例确认全部子进程退出、保存原包/搬移包身份、签名及拒绝访问/功能回执后，回收该例独占包副本，再开始下一例。失败同样保存诊断后清理，不能积累全矩阵的整套资源复制。
- 编译：编译器退出后生成Rust副本不再是运行输入，保留原始冻结源、配置和重建方式即可回收；实际链接对象/归档如仍被后续完整性核验读取，保留到该消费者结束。不得为节省空间放松核验或静默移走输入。 D24全量构建成功出口的实际回收及源/产品清单绑定核对见[CLN43](reports/2026-10-26-43-generated-rust.md)。
- 矩阵仍在构建时，可按已完成配置回收已消费的编译副本：先核对该配置两条编译路径正常退出、无遗留子进程、产品保护交接成功，确认后续读者和活动保护清单均不需要这些副本，再对选定配置分别检查句柄、持久化逐项清单并删除。不能对仍有其他配置运行的整棵构建根做闲置判定；当前配置、链接输入和在用出口脚本不动。实际记录见[CLN44](reports/2026-10-27-44-consumed-d24-compiler-copies.md)。
- 新候选替换旧候选：交接并核对实际消费者后清理旧缓存与打包副本；当前试用包、待验收产品和独有源不当垃圾删。失败日志也不随整树删除。
- 已结束的历史源码快照按消费者处理：保留独有内容与原输入清单；若逐项内容身份已绑定到另一份持久保留源，可回收重复文件并提交映射。旧快照此后需先恢复补齐再运行，保留源有恢复消费者，后续退役先交接；不能以“冻结源”名义无限保留全量重复副本。实际记录见[CLN45](reports/2026-10-27-45-duplicate-snapshots.md)。
- 每轮成功归档后核对前序内容包的消费者；仅在后继包按成员SHA/大小完整覆盖、原路径/权限映射保留并无句柄时，提交清理报告回收旧包。原回执不改写，恢复入口明确交接，不能让每轮完整内容包无限叠加。实际记录见[CLN46](reports/2026-10-27-46-superseded-archive.md)。
- 运行用例：所属进程完整回收、原始request/response/result/process与输出已保存后，当轮回收成功用例的独占临时编译文件和缓存；失败现场另行分类。中途快照仅在逐项确认被最终结果覆盖后退役。手册导出的工作源副本可在逐项绑定原输入、保留Info与程序身份回执后回收。清理先落逐项清单再删除，不在下一轮验收前继续堆积；本次实际记录见[CLN47](reports/2026-10-27-47-consumed-runtime-state.md)与[CLN48](reports/2026-10-27-48-manual-input-copies.md)。
- dump/格式测试也有明确消费出口：dump准备与第二进程恢复均完成、保存镜像/ELN身份及结果后，回收该例镜像和生成单元；格式正负面用例完成后，回收其独占编译夹具副本，保留原始准备夹具、逐例manifest和结果。重跑先重新生成或复制工作制品，不能直接读取已退役路径。实际逐项核对见[CLN54](reports/2026-10-27-54-consumed-case-artifacts.md)。
- 不把所有旧缓存再压缩一遍作为默认方案。仅保留恢复确需的最小证据；原有归档后续退役时，另记批次并更正精确恢复承诺。

本流程要求执行清理及报告，不表示已有后台清理器或仅靠目录名自动删除。中断后先恢复本次死owner的记录保护，再按精确路径复核，禁止扩大到其他对话或全机缓存。

## 如何追查问题

1. 从 `LOG.md` 找到日期/路径/变更类别，进入报告查看判断依据和保留边界。
2. 对照报告的 `source_ref`、`change_ref`、逐项 blob/SHA-256 和验证范围，区分清理前已有缺陷与清理带来的行为变化。对 tracked 路径用 `git log --follow -- PATH` 和 `git show REF:PATH` 查旧内容。
3. 将恢复内容先写入独立的 `build/recovery/CLN-ID/`，检查身份后再做隔离重建或对照；不覆盖当前工作区和试用包。恢复缓存不等于恢复已退役功能。
4. 对报告本身用 `git log --follow -- maintenance/cleanup/reports/REPORT.md` 定位它的签名提交；这样同批提交不需要写入一个不可能预知的自身哈希。已知较早的操作/删除提交必须写完整 ref，不使用含糊的“本提交”。
5. 后续发现原判断或记录有误，追加更正及证据并引用原编号；保留原决策和失败结果，不能把历史失败静默改成成功。签名提交和推送更正。

## 本次文档验收

全部报告、台账、模板与清单写齐后，集中检查 Markdown 相对链接、编号唯一性、Git refs/blob、清单计数/字节和 SHA-256、惰性补丁的隔离应用及四文件哈希。检查没有改运行时代码、Agent 规则、原始 Lisp/数据或现有试用包；不触发远端 CI。本次没有运行编译器或产品验收，历史测试结论只按各报告中的原始范围引用。


归档核验结果（2026-10-24）：六个编号/报告引用、全部新增相对链接、15项tracked删除的完整refs/blob/SHA-256、685项清单计数/字节、四文件补丁隔离重建/哈希及文档边界检查全部通过。旧汇总和零删除记录按原证据核对；本次没有重跑历史产品验收。报告和证据文件随同一签名提交交付。
